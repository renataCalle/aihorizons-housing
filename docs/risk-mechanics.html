How a parcel becomes a risk score

A site's risk is the odds, delay, and extra cost of the approval path its best building has to take. Data says what is on the lot, the zoning code says which path applies, and economics prices that path.

Three disciplines, one contract each

Engineer · facts

Reproducible inputs

  • Every fact traces to a raw file with its URL, source date and hash.
  • Hazards are stored as a share of the lot, never yes/no.
  • Missing data is unknown, never clean, and adds a check to next steps.
  • The engine is pure code: same SiteContext in, same answer out.
Regulator · rules

The code as data

  • Each rule is a row with its section and effective date, so a code change is a new version, not a rewrite.
  • The relief type in the code sets who decides: desk, administrator, ZBA or Council.
  • Overlays add procedures on top of any rung (mines, floodplain).
  • Screening language only: “by right under the code as of a date”.
Economist · prices

Risk is odds × delay × cost

  • A site is an option: worth pursuing only if expected margin after carry beats the diligence it costs.
  • Outputs are p10 / p50 / p90 ranges, because cost data is soft.
  • Next steps are ranked by value of information: the cheapest check most likely to kill the deal goes first.
  • Measured approval rates are optimistic: withdrawn cases never reach a vote.
